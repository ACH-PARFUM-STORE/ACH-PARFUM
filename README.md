# ACH PARFUM — متجر العطور المركّبة

متجر إلكتروني بالعربية (RTL) بالأسود والذهبي. HTML + CSS + JavaScript بدون خطوة بناء، وقاعدة بيانات Supabase، ويُستضاف مجاناً على GitHub Pages.

## الملفات

```
index.html      الرئيسية (عطور مميزة، النوتات، أحدث العطور، العائلات)
shop.html       كل العطور + البحث الذكي بالنوتات + الفلاتر
product.html    صفحة العطر (الهرم العطري، التركيز، الحجم، السعر)
cart.html       السلة وإتمام الطلب (بدون حساب)
account.html    تسجيل / دخول / المفضلة / سجل الطلبات
admin.html      لوحة المدير
js/config.js    ← الملف الوحيد الذي تعدّله
supabase/schema.sql   الجداول + الأمان (شغّله أولاً)
supabase/seed.sql     بيانات تجريبية (اختياري)
```

## الإعداد (حوالي 15 دقيقة)

### 1) قاعدة البيانات
1. أنشئ مشروعاً في [supabase.com](https://supabase.com).
2. من **SQL Editor → New query** الصق محتوى `supabase/schema.sql` كاملاً ثم **Run**.
3. (اختياري) شغّل `supabase/seed.sql` لعائلات ونوتات و6 عطور تجريبية. الأسعار والنوتات فيها تقريبية للتجربة فقط — احذفها قبل الإطلاق.

### 2) ربط الموقع
من **Project Settings → API** انسخ:
- **Project URL**
- مفتاح **anon / publishable**

وضعهما في `js/config.js`. هذا المفتاح مخصص ليكون علنياً، والحماية تأتي من سياسات RLS.
**لا تضع أبداً مفتاح `service_role` أو `secret` في أي ملف من الموقع.**

### 3) حساب المدير
1. افتح `account.html` وأنشئ حساباً ببريدك (هو حساب المدير).
2. إن كان تأكيد البريد مفعّلاً، أكّد بريدك أولاً.
3. من SQL Editor شغّل (مع بريدك):
   ```sql
   insert into public.admins (user_id)
   select id from auth.users where email = 'YOUR-EMAIL@example.com';
   ```
4. ادخل من `admin.html` — يعمل على أي جهاز بنفس البريد وكلمة المرور.

لا توجد أي طريقة من الموقع لإضافة مدير آخر؛ الجدول `admins` لا يقبل كتابة من المتصفح.

### 4) الاستضافة على GitHub Pages
1. ارفع محتوى المجلد إلى مستودع GitHub.
2. **Settings → Pages →** Branch: `main` / root.
3. انسخ رابط الموقع ثم في Supabase: **Authentication → URL Configuration** ضعه في **Site URL** وأضفه إلى **Redirect URLs** (ضروري لروابط تأكيد البريد واستعادة كلمة المرور).

## الاستعمال

**إضافة عطر:** لوحة التحكم → العطور → «إضافة عطر». في الأسفل جدول التركيزات × الأحجام: اكتب سعر كل خانة يدوياً، وألغِ «متوفر» لخيار نفد وحده. يمكنك إضافة/حذف تركيزات وأحجام لكل عطر.

**صور النوتات:** تبويب «النوتات العطرية» → تعديل → ارفع صورة (أو اترك الإيموجي كأيقونة بديلة).

**الاستيراد الجماعي:** تبويب «استيراد» → حمّل القالب (Excel أو CSV) → املأه → ارفعه. الأعمدة:

| العمود | مثال |
|---|---|
| الاسم (إجباري) | Sauvage |
| الماركة | Dior |
| العائلة | منعش |
| الوصف | افتتاحية حمضية... |
| الصورة | رابط https |
| مميز | 1 أو 0 |
| النوتات العليا / نوتات القلب / النوتات الأساسية | البرغموت, الفلفل |
| الخيارات | `ضربة 1\|10ml\|1500\|1; ضربة 3\|30ml\|4800\|0` |

صيغة الخيار: `تركيز|حجم|سعر|متوفر` والأخير اختياري (1 افتراضياً). العطر الموجود بنفس الاسم والماركة يُحدَّث ولا يتكرر، والنوتات والعائلات الجديدة تُنشأ تلقائياً. بعد الاستيراد يبقى كل عطر قابلاً للتعديل منفرداً.

## كيف يعمل البحث بالنوتات
اختر عدة نوتات في `shop.html`: تُرتَّب النتائج 3/3 ثم 2/3 ثم 1/3، ولا يُخفى أي تطابق جزئي (تظهر النوتات المتطابقة على كل بطاقة). داخل كل درجة يأتي المتوفر قبل غير المتوفر.

## الأمان — ما الذي يحميه الخادم فعلاً
- كل كتابة على العطور والأسعار والنوتات والصور والطلبات محصورة بـ `is_admin()` داخل قاعدة البيانات (RLS)، وليست مجرد إخفاء أزرار.
- الزبون لا يكتب في جدول الطلبات مباشرة: الطلب يمر عبر الدالة `place_order` التي **تعيد حساب الأسعار من قاعدة البيانات** وترفض الخيارات غير المتوفرة، فلا يمكن التلاعب بالسعر من المتصفح.
- العميل يرى طلباته ومفضلته وبياناته فقط.
- رفع الصور محصور بالمدير، وأنواع الصور المسموحة PNG/JPG/WEBP/GIF بحد 5MB.

## افتراضات يمكن تغييرها
- العملة «دج» (`CURRENCY` في config.js).
- لا توجد بوابة دفع: بعد الطلب يتصل بك فريقك للتأكيد.
- لا توجد كميات مخزون، فقط «متوفر / غير متوفر» لكل خيار كما طلبت.
- البحث بالنوتات يتم في المتصفح على كامل الكتالوج؛ ممتاز حتى بضعة آلاف من العطور، وإن كبر الكتالوج كثيراً يُنقل إلى دالة في قاعدة البيانات.
- صور العطور: استعمل صوراً لديك حق استعمالها.
- الطلبات من الزوار بدون حساب غير محمية ضد الإرسال الآلي المكثّف؛ إن ظهر إزعاج أضف حدّاً للمعدل أو CAPTCHA لاحقاً.
